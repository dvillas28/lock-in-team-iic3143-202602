# Habilitar almacenamiento académico S3

Daniel configura IAM y el bucket en el entorno correspondiente. La implementación
se desarrolló antes de ampliar los permisos AWS. La validación real del prefijo
`academic/` queda pendiente de esa configuración.

## Bucket, claves y acceso

- Usa un bucket privado de propósito general en la región aprobada para ese
  entorno. Activa Block Public Access y deshabilita las ACL con Bucket owner
  enforced. Mantén HTTPS y cifrado SSE-S3. El backend envía `AES256` al subir.
- La clave es `academic/materials/{institutionId}/{materialId}/{objectId}`.
  Cada identificador lo genera el servidor. UC y UTFSM tienen namespaces
  distintos. S3 crea los prefijos al guardar el primer objeto. El adaptador
  reserva `academic/submissions/` para una fase posterior.
- PostgreSQL registra los metadatos. El navegador usa los endpoints autenticados
  de NestJS. El backend valida permisos para detalle, previsualización y descarga
  y luego transmite los bytes. S3 solo recibe solicitudes del backend. El bucket
  no requiere CORS para este flujo.

## Política de ejecución

Reemplaza `BUCKET_ACADEMIX_ENTORNO` por el nombre real. Añade esta declaración a
la identidad de ejecución del backend. Mantén la declaración de avatares
separada cuando la misma identidad sirva ambos prefijos.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AcademicMaterials",
    "Effect": "Allow",
    "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
    "Resource": "arn:aws:s3:::BUCKET_ACADEMIX_ENTORNO/academic/materials/*"
  }]
}
```

El servidor usa esas tres operaciones. El mantenimiento usa su propia
credencial, con `s3:DeleteObject` sobre el mismo ARN y el siguiente permiso de
enumeración. El servidor HTTP no necesita `s3:ListBucket`.

```json
{
  "Effect": "Allow",
  "Action": "s3:ListBucket",
  "Resource": "arn:aws:s3:::BUCKET_ACADEMIX_ENTORNO",
  "Condition": {"StringLike": {"s3:prefix": "academic/materials/*"}}
}
```

El ejemplo usa SSE-S3 y no requiere permisos KMS. Si el bucket tiene
versionamiento, define con el equipo la retención de versiones anteriores.
`DeleteObject` retira el objeto actual y puede dejar versiones no vigentes.

## Variables y cambio de entorno

| Variable del backend | Desarrollo local | S3 de prueba o producción |
| --- | --- | --- |
| `ACADEMIC_STORAGE_DRIVER` | `local` | `s3` |
| `ACADEMIC_LOCAL_DIR` | `.data` o ruta persistente | — |
| `S3_ACADEMIC_BUCKET` | vacío | Bucket real del entorno |
| `AWS_REGION` | — | Región real del bucket |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | — | Si se suministran credenciales por variables |
| `AWS_SESSION_TOKEN` | — | Con credenciales temporales |

El SDK v3 usa su cadena estándar de credenciales. Inyecta la identidad desde el
gestor de secretos del despliegue. Usa credenciales temporales o un rol cuando
la plataforma lo permita. En Render, carga las variables del backend desde el
panel del servicio. En Compose, las variables AWS se leen del `.env` ignorado.
Las variables académicas son independientes de `AVATAR_STORAGE_DRIVER` y
`S3_AVATAR_BUCKET`. Si los buckets comparten las variables AWS de entorno,
usa la misma región y otorga permisos explícitos para cada prefijo.

En local, Compose conserva `/app/data/academic/` en el volumen de datos
existente. Al ejecutar NestJS directamente, la raíz relativa se resuelve
desde el directorio de trabajo del backend. Los límites configurables son
`ACADEMIC_DOCUMENT_LIMIT_MIB=20`, `ACADEMIC_IMAGE_LIMIT_MIB=10` y
`ACADEMIC_ZIP_LIMIT_MIB=50`, con un máximo de 50 MiB por categoría.

Con un driver incompleto o no disponible, el backend devuelve 503 en las
operaciones afectadas. En producción, el driver local queda deshabilitado.
Cambiar el driver cambia dónde se resuelven las referencias de la base. Usa
una base de pruebas limpia al activar S3 o migra y verifica los objetos
existentes conservando sus claves antes de cambiar un entorno con archivos.

## Prueba real en un entorno aislado

1. Configura la identidad, la región, el bucket y el driver. Aplica migraciones
   y reinicia el backend. `/ready` comprueba PostgreSQL. La prueba de conexión
   a S3 es la siguiente operación de carga autenticada.
2. Como docente, sube un PDF de dos páginas y comprueba que aparezca en el
   módulo como borrador. Daniel puede verificar el prefijo y SSE-S3 en la
   consola de AWS, con sus propios permisos operativos.
3. Abre la vista previa como docente. Publica el archivo y el módulo. Abre el
   visor como estudiante autorizado, cambia de página y descarga el archivo.
   Comprueba que la descarga de un usuario ajeno o con matrícula revocada
   devuelve 404. Compara `shasum -a 256` del original y la descarga.
4. Reinicia el backend con la misma configuración. Repite la lectura y
   descarga y vuelve a comparar el hash.
5. Elimina el recurso como docente. Verifica 404 en detalle y descarga y
   confirma la ausencia del objeto actual en AWS.
6. Registra entorno, fecha y resultado de cada paso. Las pruebas locales y el
   transporte simulado validan el código antes de esta prueba.

## Diagnóstico y recuperación

| Señal | Qué revisar |
| --- | --- |
| `AccessDenied` | Permiso sobre el ARN y prefijo exactos, política de bucket, identidad efectiva y requisito de cifrado. |
| Región incorrecta | `AWS_REGION` debe coincidir con la región del bucket. |
| Bucket incorrecto | Confirma `S3_ACADEMIC_BUCKET`, cuenta y entorno. |
| Credencial vencida o inválida | Revisa la cadena del SDK y renueva la credencial y su token juntos. |
| Error CORS | Comprueba el origen de AcademiX en `CORS_ALLOWED_ORIGINS` del backend. |
| 503 de configuración | Confirma el driver, región y bucket en el proceso. Los logs del backend están sanitizados. |

Para recuperar objetos sin referencia, ejecuta con la credencial operativa
PostgreSQL y el proveedor del mismo entorno:

```bash
pnpm --dir backend run academic:cleanup --batch=100
pnpm --dir backend run academic:cleanup --batch=100 --apply
```

El primer comando simula. El segundo elimina objetos académicos con más de
24 horas y sin referencia vigente. Continúa con `--after=<cursor>` mientras se
devuelva un cursor y repite desde el inicio en la siguiente revisión. Si falla
un borrado, el lote puede volver a ejecutarse. Nunca apliques un lifecycle
general al prefijo activo. Conserva el resultado del mantenimiento en el
registro operativo.
